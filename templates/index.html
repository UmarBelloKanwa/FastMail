📧 FastAPI Email Service

A standalone SMTP-sending microservice built on FastAPI and FastAPI-Mail, meant to be deployed on a server that supports outbound SMTP (e.g. a VM or container) so a serverless main app that can't send SMTP directly can call it over HTTP instead.

📁 Project Structure

project/
├── main.py
├── schema.py
├── templates/
│   ├── index.html
│   └── welcome.html      (example Jinja2 template)
├── requirements.txt
└── .env.example

⚙️ Configuration

Copy .env.example to .env and fill in your SMTP credentials. Every endpoint will use these as the default sender config unless a request includes its own config object, which lets a single deployment send on behalf of multiple accounts.

✉️ Endpoints

GET /health — liveness check

POST /send/email

Plain/HTML email with optional base64 attachments.

{
  "config": { "...": "optional, falls back to env vars" },
  "message": {
    "recipients": ["someone@example.com"],
    "subject": "Hello",
    "body": "<p>Hi there</p>",
    "subtype": "html",
    "cc": [], "bcc": [], "reply_to": [],
    "attachments": [
      { "filename": "invoice.pdf", "content_base64": "...", "content_type": "application/pdf" }
    ]
  }
}

POST /send/email/with-attachments

Same as above, but as multipart/form-data: a message form field containing the same JSON (minus attachments), an optional config form field, and one or more real files. Cheaper than base64 for large attachments.

POST /send/email/template

Renders a Jinja2 template from templates/ as the email body. 

{
  "message": {
    "recipients": ["someone@example.com"],
    "subject": "Welcome!",
    "template_body": { "name": "Ada", "message": "Thanks for signing up." }
  },
  "template_name": "welcome.html"
}

⚠️ Notes

Feature Supported
SMTP over STARTTLS / SSL ✅
Plain & HTML bodies ✅
CC / BCC / Reply-To ✅
Custom headers ✅
Attachments (base64 or multipart) ✅
Jinja2 templated emails ✅
Per-request sender config (multi-tenant) ✅

uvicorn main:app --host 0.0.0.0 --port 5001 --reload
